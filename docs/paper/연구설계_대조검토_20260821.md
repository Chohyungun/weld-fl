## 2. 문서가 앞선 지점 — 반영안

### (가) 가상 회사 분할의 이질성 정량화

**지적 검증: 유효하다.** 우리는 자연 이질성 3축(재질·클래스 분포·규모)을 서술로만 근거
삼고 **수치로 보고하지 않는다.** "얼마나 non-IID인가"에 답이 없다. 심사에서 반드시 나온다.

**반영안 — 분할 매니페스트만으로 산출 가능하다. 새 실험이 필요 없다.**

| 지표 | 정의 | 무엇을 보이나 |
|---|---|---|
| 클래스 분포 JSD | 클라이언트별 클래스 분포 `p_k`와 전역 분포 `p_g`의 Jensen-Shannon divergence. 클라이언트별 값 + 최대·평균 | label skew의 크기. 0이면 IID |
| **실현 농도 역추정** | 명목 농도 (1/3, 1/6)에 대해 실현된 배정에서 α를 역추정해 병기 | **"명목 α=0.5인데 실현은 얼마였나"** — 재추첨 수용 밴드가 있어 명목과 실현이 다르다. 가장 직접적인 답 |
| 규모 불균형 | 클라이언트 표본 수 비율과 Gini 계수 | quantity skew |
| 재질 구성비 | 클라이언트별 ST/AL 비율 (C3는 AL 100%) | feature skew. 자연 이질성의 근거 |
| 라벨 공간 커버리지 | 클라이언트별 등장 클래스 수, 0장 클래스 개수 | 의도된 극단 배정의 실현 여부 |

- 산출 위치: **A의 분할 산출물에 부속 리포트로**(manifest에서 재계산 가능하므로 A 소관),
  **보고는 D의 결과표 파이프라인**. → **A·D 협의 대상, 총괄 배분 요청.**
- 논문 배치: **연구 설계 절 + 클래스×회사 히트맵(그림 후보 R3)과 같은 자리.** 히트맵이
  그림이라면 이 표가 그 수치판이다.
- 비용: 매니페스트 확정 시점에 스크립트 한 번. 실험 재실행 없음.

**관련 문헌 1건 확보.** Hegiste, V., Legler, T., Ruskowski, M. (2023), *Federated Object
Detection for Quality Inspection in Shared Production*, arXiv:2306.17645 — 제조 다중 공장
환경의 연합 객체검출 + non-IID로, **우리 분리·연합 칸과 설정이 가장 가깝다.** 제목·저자·
연도는 확인했으나 **이질성 정량화 지표 사용 여부는 초록 수준에서 미확정**이라 ◐로 둔다.
본문 확인 후 관련연구에 넣는다. (Notion 필독 논문 목록에서 발견 — 그쪽 목록에 우리
`논문_리스트.md`에 없는 문헌이 여럿 있다. §4 참조)

### (나) 합성데이터 다양성 저하

**지적 검증: 유효하다. 그리고 이건 자기모순 위험이다.** 우리는 선행 연구(WeldLLM)의
텍스트가 150+ 템플릿 채우기라는 점을 비판하고 그것을 조항 정확도 축 신설의 근거로 삼는다
(필수 문장 #6). 그런데 우리 합성문도 골격 + 표현 변주다. **우리 쪽 다양성을 수치로
보고하지 않으면 같은 비판이 그대로 돌아온다.**

**반영안 — 핵심은 "문형 다양도"다.**

수치와 조항은 어차피 골격에서 오므로(수치 잠금), **다양성은 문형에서만 나온다.** 따라서
생성문에서 골격 유래 토큰(수치·단위·조항 ID·결함 코드·등급)을 마스킹한 뒤 남은 문형을 센다.

1. **문형 고유도** = 마스킹 후 고유 문형 수 / 총 채택 건수. 자산별(QA·판정추론·D4) 산출.
2. **상위 문형 점유율** = 빈발 문형 상위 10개가 차지하는 비율. 이게 높으면 수렴한 것이다.
3. **distinct-2 / distinct-3** (마스킹 후 n-gram 다양도) — 보조.
4. **조합 내 다양성** = 같은 골격 조합에서 나온 생성문들 사이의 문형 중복률. 조합당 상한이
   40이므로 이 안에서 40개가 사실상 같은 문장이면 상한의 의미가 없다.

- 보고: B의 `validation_report`에 다양성 절을 추가하고 **논문 부록에 자산별 문형 고유도와
  상위 10개 점유율을 싣는다.** 통과율과 나란히 놓는다.
- 사전 기준은 걸지 않는다(무엇이 "충분한 다양성"인지 근거가 없다). **측정하고 보고**하는
  것까지가 이번 범위이고, 값이 극단적이면(예: 상위 10개가 절반 이상) 그때 총괄 회부.
- 임베딩 기반 의미 중복도는 **쓰지 않는다.** 판정문은 의미가 좁아서(합격/불합격 + 조항)
  의미 유사도가 높게 나오는 게 정상이라 신호가 되지 않는다. 문형이 맞는 축이다.

### (다) 검증 실패 샘플 처리정책 — B에 넘길 구체안

**총괄 판정 수용: 재생성 금지는 유지한다.** 자기검증 루프를 막는 원칙이므로 바꾸지 않는다.
아래는 **기록과 보고만 추가**하는 안이라 레드라인과 충돌하지 않는다.

**핵심 착안: 난이도 축을 새로 만들 필요가 없다.** B 스펙 §4-3이 이미 샘플마다
`sample_bucket`을 부여한다 — 합격(0, 0.9L) / 불합격(1.1L, 2.5L] / 경계 [0.9L, 1.1L],
그리고 경계 내부는 `=L` · 하경계 · 상경계 3분할. **이 필드를 폐기 로그에 그대로 실으면
난이도 구간별 폐기 분포가 바로 나온다.** 새 설계가 아니라 기존 필드의 재사용이다.

B에 요청할 것 5가지:

1. **폐기 레코드에 `sample_bucket`을 보존한다.** 현재 폐기 사유 코드 5종
   (`missing_value` / `extra_value` / `changed_value` / `verdict_flip` / `format_violation`)은
   기록되지만, 폐기된 샘플이 어느 버킷이었는지는 남지 않는다. 폐기 로그 스키마에
   `sample_bucket`, `combo_key`(조합 해시), `stage`(1단계 규칙 / 2단계 Judge / 3단계 표본)를
   추가한다. 생성문 본문은 남기지 않아도 된다 — 메타만으로 분포가 나온다.
2. **교차 집계표를 산출물로 만든다.** `실패 사유 × sample_bucket` 교차표에 셀마다
   {생성 시도 수, 통과 수, 폐기율}. 자산별(QA·판정추론·D4)로 따로. `validation_report`에 포함.
3. **G2 감사를 두 번 돌린다 — 이것이 가장 중요한 한 줄.** B 스펙 G2는 버킷 비율을
   전체·조합별 ±2%p로 검사하는데, 이는 **생성 시점** 비율이다. **3단계 검증 완료 후 채택분에
   대해 같은 검사를 한 번 더 돌리고 두 비율을 병기**한다. 선택 편향이 있으면 여기서
   바로 드러난다. 생성 시 경계 20%가 채택 후 12%로 내려갔다면 그 자체가 결과다.
4. **판정 기준을 사전 등록한다**(사후 합리화 방지 — B가 이미 함정 #2에서 쓰는 방식).
   제안: **경계 구간 폐기율 ÷ 비경계 구간 폐기율 ≥ 1.5**, 또는 두 비율 차의 95% 신뢰구간이
   0을 포함하지 않으면 → **"경계 사례 선택 편향 있음"으로 판정하고 논문에 보고**한다.
   수치는 파일럿 분포를 보고 메인 생성 **전에** 고정하고 이후 변경 금지.
5. **논문 보고 형식까지 정해 둔다.** 편향이 확인되면 통과율 표 옆에 버킷별 폐기율을 싣고,
   한계 절에 한 문장을 넣는다. 초안:
   > 검증에서 탈락한 샘플은 재생성하지 않고 폐기했으며, 그 결과 허용치 경계 구간의 샘플이
   > 비경계 구간보다 {}배 높은 비율로 제거되었다. 학습 데이터가 경계 판정에서 상대적으로
   > 쉬운 쪽으로 치우쳤을 가능성이 있으며, 본 연구는 이를 보정하지 않고 분포를 그대로 보고한다.

**하지 말자고 제안하는 것 — 버킷별 차등 오버샘플링.** B 스펙 §7-2는 목표량 ×1.3 사전
초과 생성을 한다. 경계 버킷만 계수를 올리면 형식상 "재생성"이 아니라 원칙 위반은 아니다.
그러나 **보정하는 순간 현상을 깨끗하게 보고할 수 없게 된다.** 우리 방어는 숨기지 않는
것이므로 **미적용을 기본으로 권고**하되, 이건 **총괄 판단 사항**으로 올린다.
