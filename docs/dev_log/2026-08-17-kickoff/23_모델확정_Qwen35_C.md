# 모델 확정 보고 — Qwen3.5-4B 네이티브 멀티모달 여부 (트랙 C)

2026-08-21 · 총괄 확인 요청에 대한 답신 · 의사결정로그 미정 항목 "Qwen3.5 네이티브 멀티모달 여부" 종결 요청

## 0. 결론

**Qwen3.5-4B는 네이티브 멀티모달이 맞다. 통합형과 분리형 판정부가 동일 체크포인트를
공유한다.** 따라서 **백본 비동일 교란 변수는 발생하지 않는다** — 우리 논문에서 가장 아픈
지점으로 지목된 곳이 실측으로 닫혔다.

사용자 대외 연구설계 문서(8/16판)의 "통합형 Qwen2.5-VL 3B / 판정부 Qwen3.5 4B" 조합은
**폐기를 권고한다.** 그 조합은 백본이 실제로 갈라져 RQ2에 교란 변수를 만드는데, 실물
확인 결과 그럴 이유가 없어졌다. `docs/개발규약.md`의 "동일 체크포인트 공유" 서술이 옳다.

## 1. 확인 방법과 증거

문서·블로그가 아니라 **HuggingFace 배포 실물 config**로 확인했다. 가중치는 받지 않고
`config.json`·`preprocessor_config.json`·`tokenizer_config.json`만 조회했다
(스크립트는 세션 스크래치패드, 재실행 가능).

`Qwen/Qwen3.5-4B` (최종수정 2026-03-02):

| 항목 | 실측값 | 판정 |
|---|---|---|
| `architectures` | `["Qwen3_5ForConditionalGeneration"]` | VL 계열 진입점 |
| `model_type` | `qwen3_5` (하위 `text_config.model_type = qwen3_5_text`) | 언어부가 하위 설정으로 분리된 early-fusion 구조 |
| `vision_config` | 존재 — `depth 24, hidden_size 1024, patch_size 16, spatial_merge_size 2, out_hidden_size 2560` | **비전 인코더 내장** |
| 비전 토큰 | `image_token_id`, `video_token_id`, `vision_start_token_id`, `vision_end_token_id` 전부 존재 | 멀티모달 입력 경로 존재 |
| 프로세서 | `preprocessor_config.json` + `video_preprocessor_config.json` 존재, `processor_class: Qwen3VLProcessor` | 이미지·비디오 프로세서 동반 |

모델 카드도 "Causal Language Model with **Vision Encoder**", "Unified Vision-Language
Foundation: Early fusion training on multimodal tokens"로 서술하며 RefCOCO 등 공간
grounding 벤치마크를 싣는다. **config 실물과 모델 카드가 일치한다.**

대조군으로 같이 조회한 `Qwen/Qwen2.5-VL-3B-Instruct`(patch 14·merge 2)와
`Qwen/Qwen3-VL-4B-Instruct`(patch 16·merge 2)도 같은 구조를 보였고, Qwen3.5-4B의
`vision_config`는 Qwen3-VL-4B와 거의 동일하다(depth·hidden·patch·merge 일치, `deepstack_visual_indexes`만
`[5,11,17]` → `[]`로 다름).

참고: `Qwen/Qwen3.5-4B-Instruct`는 **존재하지 않는다**. 배포는 `Qwen/Qwen3.5-4B` 단일
리포이며 chat template을 동반하므로 지시 학습본으로 그대로 쓴다.

## 2. 5칸 공통 고정 8종에 미치는 영향

동일 체크포인트가 되면서 **통제가 약해지는 것이 아니라 강해진다.**

| # | 공통 고정 항목 | 영향 |
|---|---|---|
| 1 | 기본 모델 체크포인트 | **강화.** 통합형 2칸 + 분리형 판정부(3칸 공통 동결)가 전부 같은 sha256에서 출발한다. "5칸 동일 출발점 증명"이 문자 그대로 성립한다. 배경지식 학습(지시·추론)도 **한 번만 수행해 두 구조가 공유**하므로, 두 벌 학습에서 생기던 미세한 차이 자체가 없어진다 |
| 2 | 어댑터 설정 | 동일 적용. 통합형은 비전 인코더 동결 + 언어부만 어댑터, 판정부는 언어부만 쓰므로 `target_modules`가 자연히 같아진다 |
| 3 | 최적화 | 영향 없음 (동일) |
| 4 | 전처리 | 통합형만 이미지 전처리를 탄다. 분리형 판정부는 텍스트 입력이므로 이미지 전처리가 없다. **"구조 내 동일" 원칙 유지**(통합형 2칸끼리 동일, 분리형 3칸끼리 동일) |
| 5 | 프롬프트·출력 스키마 | **출력 스키마는 5칸 동일, 프롬프트는 구조별로 고정.** 입력이 다르므로(이미지 vs 검출 JSON+조항) 프롬프트가 같을 수 없다. 기존 설계와 일치하며(분리형은 `rag/prompts/verdict_v1.txt` 공통), 여기에 **chat template(7,756자)도 스냅샷 해시에 포함**한다 — 같은 체크포인트를 쓰므로 두 구조가 같은 템플릿을 탄다 |
| 6 | 검색 설정 | 분리형 전용. 통합형에 검색을 붙이지 않는 비대칭은 **의도된 대비축**이므로 유지(실험설계 7장) |
| 7 | 디코딩 | 동일. 같은 체크포인트라 생성 설정도 한 벌로 고정된다 |
| 8 | 시드 | 영향 없음 |

## 3. 남는 비대칭 — 무엇이 교란 변수이고 무엇이 아닌가

백본이 같아졌다고 두 구조가 모든 면에서 같아지는 것은 아니다. 남는 차이를 **의도된 것**과
**한계로 선언할 것**으로 나눈다.

| 차이 | 성격 |
|---|---|
| 입력 양식 (이미지 토큰 vs 구조화 검출 JSON) | **의도된 대비축.** 이것이 RQ2가 비교하려는 대상 자체다. 제거하면 실험이 성립하지 않는다 |
| 통합형은 규정 검색 없음, 분리형은 있음 | **의도된 대비축**(실험설계 7장). 판정 근거 신뢰도 비교의 축이며, 공정성 지적 대비용 보조 조건 1회를 부록에 둔다 |
| 분리형에만 YOLO11s(9.4M) 추가 | **측정 대상.** 처리 속도·자원·통신량 항목에서 정량화한다. 숨기지 않고 표에 싣는다 |
| 통합형은 비전 인코더를 학습 경로에 포함(동결하되 forward 통과) | 파라미터 수·VRAM·latency 차이로 나타나며 §8-1에서 측정된다 |

## 4. 한계 절 서술 — 재작성 초안 (E 트랙 앞)

기존 서술(실험설계 5-3, E 스펙 L1) **"통합형은 VLM, 분리형 판정부는 LLM이라 완전히 같은
백본을 쓸 수 없다 — 같은 계열로 맞추고 한계 절에 선언한다"는 이제 사실과 다르다.**
Qwen3.5-4B가 네이티브 멀티모달이라 같은 백본을 쓸 수 있다. 아래로 교체를 제안한다.

> **초안 (한계 절 및 방법 절 공용).**
> 두 구조는 동일한 오픈 가중치 체크포인트(Qwen3.5-4B, 네이티브 멀티모달)에서 출발한다.
> 통합형은 이 모델의 비전·언어 경로를 함께 사용하고, 분리형 판정부는 같은 체크포인트의
> 언어 경로만 사용한다. 배경지식 학습(지시·추론 단계)도 한 번만 수행해 두 구조가
> 공유하므로, 두 구조의 언어 능력은 동일한 출발점에서 통제된다. 선행 연구가 통합형과
> 분리형을 비교할 때 흔히 남는 백본 차이 교란은 이 설계에서 발생하지 않는다.
>
> 남는 비대칭은 세 가지이며 모두 의도된 것이거나 측정 대상이다. 첫째, 입력 양식이 다르다
> (통합형은 이미지, 분리형 판정부는 검출기가 산출한 구조화 결과). 이는 두 구조의 정의
> 자체이며 이 연구가 비교하려는 대상이다. 둘째, 분리형에만 규정 검색이 결합된다. 이
> 비대칭이 판정 근거 신뢰도 비교의 대비축이므로 제거하지 않았고, 공정성 검토를 위해
> 통합형에 검색 결과를 컨텍스트로 제공한 보조 조건을 부록에 함께 보고한다. 셋째, 분리형은
> 검출 모델(YOLO11s, 9.4M)을 추가로 사용하므로 총 파라미터와 처리 속도가 다르다. 이는
> 감출 차이가 아니라 구조 선택의 비용이므로 처리 속도·자원 항목에서 정량 보고한다.

**E 트랙 조치 요청**: 위 서술로 L1 항목을 교체하고, 필수 문장 체크리스트의 "백본 비동일"
항목을 "백본 동일 + 입력 양식 비대칭"으로 갱신. (타 트랙 소유 파일이므로 C는 수정하지 않았다.)

## 5. 부수 발견 4건 — 다른 결정에 영향

실물 확인 과정에서 나온 것으로, 전부 이미 내린 결정의 이행 방식에 영향을 준다.

### (1) `min_pixels`/`max_pixels` 키가 없다 — Q15 이행 방식 수정 필요 (D와 공유 사항)

Qwen3.5-4B의 `preprocessor_config.json`은 `min_pixels`/`max_pixels`가 아니라
**`size: {shortest_edge: 65536, longest_edge: 16777216}`** 형식이다
(Qwen2.5-VL은 `min_pixels: 3136, max_pixels: 12845056`). Qwen3-VL도 `size` 형식이다.

동결된 **Q15(“`min/max_pixels`를 base.yaml에 공통 고정, 프로파일 override 금지”)의 취지는
그대로 유효하지만, 고정해야 할 키 이름이 다르다.** `configs/base.yaml`에는
`size.shortest_edge`·`size.longest_edge`를 고정하고, 프로파일 yaml에는 이 키들을 두지
않는다(어길 수단 제거 원칙). C의 `CoordCfg`도 두 표기를 모두 담을 수 있게 두었다.

### (2) `factor = patch_size × merge_size = 16 × 2 = 32`

Qwen2.5-VL은 28(14×2), Qwen3.5-4B와 Qwen3-VL은 32다. **factor 하드코딩 금지 결정이 옳았음이
실물로 확인됐다.** 값은 processor config에서 읽고 `factor == patch_size × merge_size`를
assert한다.

### (3) 언어부가 하이브리드(SSM/linear attention) 아키텍처다 — 함정 #2·#3에 영향

`text_config`에 `linear_conv_kernel_dim`, `linear_num_key_heads`, `linear_num_value_heads`,
`mamba_ssm_dtype: float32`, `mtp_num_hidden_layers: 1` 등이 있다. 순수 트랜스포머가 아니다.
두 가지가 걸린다.

- **LoRA target (함정 #3)**: `target_modules="all-linear"` 금지 결정이 더 중요해졌다.
  SSM 프로젝션·conv 계층까지 어댑터가 붙으면 집계 거동을 예측할 수 없다. 채택 시점
  `named_modules()` 전수 덤프로 **명시 target 목록**을 확정한다(이미 결정된 절차).
- **FL 집계 buffer (함정 #2)**: RMSNorm은 buffer-free지만 **SSM 계열은 conv state 등
  persistent buffer를 가질 수 있다.** 12a 함정 #2의 V10(`named_buffers()` 전수 검증)을
  통합형 FL 착수 전 **필수 게이트**로 승격한다. 검출부의 BatchNorm 처방과 별개 사안이다.

### (4) 배포 `generation_config.json`이 없다 — 레지스트리 #5 갱신

Qwen3.5-4B 리포에는 `generation_config.json`이 **없다**. 즉 숨은 기본값 #5(Qwen 배포
generation_config가 `do_sample: true`·`temperature 0.7`·`repetition_penalty 1.1`을 켠다)의
경로가 **이 모델에서는 발생하지 않는다.** 다만 처방(추론 진입점에서 GenerationConfig를
백지에서 명시 구성 + `assert do_sample == False` + 실효 설정 MLflow 로깅)은 **그대로
유지한다** — 부재를 확인한 것과 명시 고정하는 것은 다른 일이고, 향후 리포에 파일이 추가될
수 있다. 레지스트리 #5에 이 확인 결과를 기록했다.

## 6. 좌표 규약에 대한 함의 (변경 없음, 근거 강화)

Qwen3.5-4B의 `processor_class`가 **`Qwen3VLProcessor`**이고 `vision_config`가 Qwen3-VL과
거의 동일하다. Qwen3-VL은 공식 쿡북에서 **0~1000 상대 좌표로 회귀**했음이 확인돼 있으므로,
우리 기본값 `NORM_1000`을 유지할 근거가 강해졌다. **다만 문서가 아니라 카나리아-1(제로샷
grounding argmax 판별) 실측이 최종 판정이라는 원칙은 그대로다** — 모델 카드에 좌표 규약이
여전히 미기재이기 때문이다. `coord_space` 값 교체 구조가 이 불확실성을 흡수한다.

## 7. 총괄 조치 요청

1. **의사결정로그 미정 항목 "Qwen3.5 네이티브 멀티모달 여부" 종결** — 확정(멀티모달 맞음),
   결과: 통합형·판정부 동일 체크포인트 공유, 백본 통제 문제 해소. (정본 수정은 총괄 소관이라
   C는 손대지 않았다.)
2. **실험설계 5-3 및 리스크 R7 갱신** — "완전히 같은 백본을 쓸 수 없다"는 서술과
   "백본 비동일 공정성 지적" 리스크를 §4 초안으로 교체.
3. **사용자 대외 문서(8/16판) 정정 안내** — 통합형 Qwen2.5-VL 3B / 판정부 Qwen3.5 4B 조합
   폐기, Qwen3.5-4B 단일로 통일.
4. **E 트랙에 §4 한계 절 초안 라우팅**, **D 트랙에 §5-(1) Q15 키 이름 변경 통지.**
