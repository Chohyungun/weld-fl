# 통합형 VLM 구현 명세(30번) 검토 — 트랙 C

2026-08-21 · Phase 1 착수 전 검토 · 대상 `30_통합형VLM_구현명세.md` (1,707행, 미커밋)

이 명세는 트랙 C의 스펙을 입력으로 썼지만 C가 쓴 것이 아니다. 총괄 지시에 따라 착수 전에
검증하고, 사실 주장은 실물로 확인했다. 결론부터: **명세의 핵심 판정은 옳고, 특히 G2
재정의와 판정 5는 C 스펙의 결함을 정확히 짚었다.** 구현 전에 해소가 필요한 지점 4건을 아래
적는다.

---

## 1. 실물로 검증한 사실 주장 3건 — 전부 확인됨

### (1) bnb `Linear4bit`이 `register_buffer` 없이 state_dict에 주입한다 — **사실**

`bitsandbytes 0.50.1`의 `Linear4bit._save_to_state_dict` 소스를 확인했다.

```python
super()._save_to_state_dict(destination, prefix, keep_vars)   # weight, bias
if getattr(self.weight, "quant_state", None) is not None:
    for k, v in self.weight.quant_state.as_dict(packed=True).items():
        destination[prefix + "weight." + k] = v if keep_vars else v.detach()
```

`register_buffer` 경로를 거치지 않고 `destination`에 직접 넣는다. 따라서
`state_dict ∩ named_buffers`로 정의한 게이트는 이 상태를 **구조적으로 볼 수 없다.**
명세의 지적이 정확하다.

한 가지 덧붙인다. 양자화 **전**(`quant_state is None`)에는 주입이 일어나지 않아
`X = state_dict − P − B`가 빈 집합이다(CPU에서 `Linear4bit(8,8)` 생성 후 실측: `X = []`).
즉 이 항목은 **NF4 실로드 이후에만 관찰된다.** 명세가 G2를 "가중치 필요: 예 (NF4 실로드)"로
표시한 것과 정합하며, meta device 프로브(G1)로는 잡히지 않는다는 뜻이기도 하다.

### (2) `named_parameters(remove_duplicate=False)`가 tied weight 오탐을 막는다 — **사실**

tie된 소형 모델로 실측했다.

| 정의 | 결과 |
|---|---|
| `X = state_dict − named_parameters() − buffers` (기본 dedup) | `['lm_head.weight']` ← **오탐** |
| `X = state_dict − named_parameters(remove_duplicate=False) − buffers` | `[]` ← 정상 |

`remove_duplicate=False`가 핵심이라는 명세 서술이 맞다.

### (3) 판정 5의 산술 — **사실이고 수치까지 정확**

`NORM_1000`, 1280×720, x를 0~1279 전수로 돌려 확인했다(예산 `roundtrip_budget_px` = 0.64px).

| 경로 | 최대 오차 | 예산 초과 |
|---|---|---|
| 현행 — 역변환 정수화 0회 | 0.6400px | **0 / 1280 (0.0%)** |
| 관점 3안 — 각 방향 1회 | 1.0000px | **280 / 1280 (21.9%)** |

명세가 든 사례도 그대로 재현된다: `x1=2px → to_model 1.5625 → quantize 2 → to_px 2.56 →
quantize 3`, 오차 1.0px. **명세의 "W=1280에서 21.9%"가 소수점까지 일치한다.**

**다만 표현을 하나 정정한다.** 판정 5는 "관점 3의 원칙을 기각"한다고 썼는데, **현행
`vlm/coords.py`는 이미 역변환 정수화를 하지 않는다.** `roundtrip_error_px`는
`to_model → quantize → to_px`까지만 수행하고 결과를 float로 돌려준다(실측 0.56px).
따라서 판정 5는 C 구현의 변경을 요구하는 것이 아니라 **현행 설계를 확인해 주는 판정**이며,
기각 대상은 후속 모듈에 정수화를 한 번 더 넣자는 제안이다. 구현자가 "coords.py를 고쳐야
한다"로 읽지 않도록 문구를 다듬는 편이 안전하다.

## 2. 해소가 필요한 지점 4건

### [중요] (a) 판정 5의 논리가 D 어댑터 정수화에 그대로 적용된다 — 재검토 필요

판정 5는 C의 역변환 직후 정수화를 없앴다. 그런데 계약 #4 §3-4는 **D 어댑터 경계에서
`int(floor(v+0.5))` 최종 1회**를 여전히 규정한다. 그 연산은 위 검증표의 "관점 3안"과
**산술적으로 동일하다** — 역변환된 원본 픽셀 좌표를 정수화하는 같은 단계다.

즉 오차가 사라진 것이 아니라 **한 단계 뒤로 밀렸다.** 그리고 D 단계의 정수화는 왕복 예산
검사 대상이 아니라 최종 채점 값이므로 게이트에 걸리지 않는다. 명세가 지적한 부수 피해
(소형 결함에 손실이 집중돼 계통 편향)가 **검출되지 않는 형태로** 남는다. 슬래그혼입이
최소 클래스(1,140장)이고 D가 초소형 박스 픽스처를 요구한 근거가 바로 이것이었다.

D 스펙 §3-4의 정당화는 "채점 재현성이 서브픽셀 정밀도보다 우선"이었다. 그러나 float
IoU 계산도 결정론적이므로 재현성은 정수화 없이도 성립한다. 정수화의 실익이 크지 않고
소형 박스에 계통적으로 불리하다.

**제안**: `bbox_px`를 float로 유지하고 D의 어댑터 경계 정수화를 제거하는 안을 D와 함께
검토한다. 계약 #4 스키마는 이미 `items: {"type": "number"}`라 float를 허용하므로 스키마
변경은 필요 없다. **C 단독으로 정할 수 없는 사안이라 총괄 안건으로 올린다.**

### (b) `target_format.py`의 테스트 2건이 D의 미구현 모듈에 역의존한다

명세 4-1의 테스트 목록에 `test_parse_error_어휘가_계약_ParseError의_부분집합이다`와
`test_VERDICTS가_evaluation_schema_Verdict와_같다`가 있다. 둘 다 `evaluation/schema.py`를
읽어야 하는데 **저장소에 `evaluation/` 디렉터리가 아직 없다.** Phase 1의 목적이 D 언블록인데
그 산출물의 테스트가 D 구현을 선행 조건으로 요구하는 역방향 의존이다.

**제안**: 2단계로 나눈다. 지금은 명세가 적시한 어휘를 상수로 고정하고 자체 정합성만
검사하며, D의 `evaluation/schema.py`가 들어온 뒤 대조 테스트를 `importorskip`으로 추가한다.
게이트 반려 이력(선택적 의존성 없이 스위트가 완주해야 한다)과 같은 처리다.

### (c) `detection` ↔ `fl` 양방향 의존이 생긴다 — 차단 사유는 아니나 고정이 필요하다

명세 4-2는 `derive_seed`를 `fl/seeding.py`로 옮기고 `detection.round_runner`가 재수출하게
한다. 그러면 `detection → fl`이 생기는데, 현재 이미 `fl.aggregate → detection.serialize`가
있어 패키지 단위로 양방향이 된다.

모듈 단위로는 순환이 아니므로 런타임 오류는 나지 않는다(`fl.seeding`은 `detection`을
import하지 않고, 두 `__init__.py`가 모두 비어 있다). 소유 자체는 `fl`이 맞다고 본다 —
시드 파생과 스텝 예산은 라운드·클라이언트 개념에 종속되고 검출 칸도 연합을 하기 때문이다.

**제안**: 양방향을 허용하되 **순환 부재를 테스트로 고정**한다. `__init__.py` 두 개가 비어
있어야 성립하는 보증이므로, 그 조건을 AST 테스트로 박아 둔다(`vlm/__init__.py`에 이미
같은 취지의 테스트가 있다).

### (d) C 스펙 §6 Q6의 `round(...)` 표기는 명세가 옳다 — 개정 대상

C 스펙 Q6은 `S_k = max(1, round(0.5 × n_k / B_eff))`로 적었다. 파이썬 내장 `round`는
banker's rounding이라 `n_k ≡ 32 (mod 64)`에서 값이 갈린다. 명세 4-2의
`max(1, int(math.floor(epoch_frac * n_k / effective_batch + 0.5)))`가 정확하며,
`coords.quantize`가 같은 이유로 내장 `round`를 배제한 것과 규칙이 일치한다.
**C 스펙 Q6을 명세 표기로 개정한다.**

## 3. 동의하는 판정 (이견 없음)

| 판정 | 평가 |
|---|---|
| G2 재정의 (P/B/X 3집합 + 교환 폐포 등식) | C 스펙의 V10(`named_buffers` 전수 검증)은 **학습 모드·`use_cache=False`에서 반드시 통과하는 게이트**였다. 명세의 지적이 옳고, "진짜 위험은 학습되는데 교환되지 않는 파라미터"라는 재정의가 정확하다. G2-3의 집합 등식(부분집합 아님, 완전 일치)이 핵심이다 |
| 판정 4 (`n_k_effective`) | 감사가 항진명제가 된다는 지적이 맞다. 폐기가 긴 샘플에 집중돼 C3이 구조적으로 손해를 본다는 것도 RQ3 주인공이라 특히 중요하다 |
| 판정 8 (단일 가상 순열) | C 스펙 Q7의 결함이 맞다. `(1/2)^6 = 1.5625%`, C3에서 약 125개 페어 미노출 계산을 확인했다. E가 분수인 통합·연합에만 생기는 비대칭이라는 지적이 정확하다 |
| 판정 9 (LoRA dropout = 0.0) | micro_batch가 난수 소비 측면에서 중립이 되게 하는 조치. 1시드라 반복 측정으로 흡수할 수 없다는 근거가 타당하다 |
| 판정 13 (어댑터 wire fp32) | C 스펙과 동일 결론 |
