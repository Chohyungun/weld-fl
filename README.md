## 무엇을 하는 연구인가

조선소마다 용접 검사 데이터가 있지만 보안상 밖으로 내보낼 수 없다.
**데이터를 한곳에 모으지 않고도 모아서 학습한 것과 비슷한 성능이 나오는가**를 측정하고,
그 조건 위에 얹을 모델 구조로 **통합형과 분리형 중 어느 쪽이 나은지**를 같은 프로토콜로 비교한다.

| 연구 질문 | 내용 |
|---|---|
| RQ1 | 데이터를 내보내지 않는 조건에서 중앙집중 학습 성능을 얼마나 회복하는가 |
| **RQ2** | 같은 연합 조건에서 통합형과 분리형 중 어느 쪽이 나은가 **(주 기여)** |
| RQ3 | 데이터가 적은 기업이 연합 참여로 얻는 이득이 있는가 |

## 실험 구조 — 다섯 칸

|            | 로컬 단독 | 중앙집중 | 연합학습 |
|------------|----------|---------|---------|
| **통합형** | 제외 ※    | 통합·중앙 | 통합·연합 |
| **분리형** | 분리·로컬 | 분리·중앙 | 분리·연합 |

- **통합형** — 용접 사진을 비전-언어 모델에 넣어 결함 판단과 판정문 작성을 한 번에 수행
- **분리형** — 검출 모델이 결함의 종류·위치·크기를 산출하고, 언어모델이 규정을 검색해 합부와 근거 조항을 정리
- ※ 회사마다 대형 모델을 단독 구축하는 상황은 현실적 도입 형태가 아니어서 비교에서 제외

헤드라인 수치는 **회복률 = (연합 − 로컬) / (중앙집중 − 로컬) × 100%** 이며,
기준 지표는 결과 확인 **이전에** Macro-F1로 고정했다(사후 지표 선택 방지).

## 재현성을 위해 고정한 것

이 연구의 주장은 "다섯 칸을 같은 조건에서 돌렸다"에 걸려 있다. 그래서 아래를 규칙으로 못박았다.

- **조기 종료 금지**, 마지막 체크포인트 채점 — 학습량 등가 `R × E = N`이 공정성 주장의 근거
- **평가셋을 회사별 분할보다 먼저 분리**, 중복 묶음 단위로 분할 (누수 차단)
- **다섯 칸 출력을 공통 스키마로 변환한 뒤 단일 채점기로 채점**
- 생성 모델이 자기 결과를 검증하지 않음 / 재시도·재프롬프트 없이 greedy 1회
- corpus·색인·분할에 스냅샷 해시 부여 후 재생성 금지

프레임워크 기본값이 위 선언을 조용히 무력화하는 경우를 여섯 건 찾아 기록했다
([숨은 기본값 레지스트리](docs/dev_log/2026-08-17-kickoff/22_숨은기본값_레지스트리_C.md)).
원칙은 **선언이 아니라 실사용을 기록하고, 불일치를 실패로 승격한다**.

## 저장소 구조

```
configs/      라벨 사상표 · GPU 프로파일 · 실험 설정
data/         수집 → 변환 → 중복 묶음 → 분할 → 매니페스트
corpus/       규정 파싱 · 허용치 표 · 합성 데이터 생성과 3단계 검증
detection/    분리형 검출 학습
vlm/          통합형 학습 · 좌표 규약
fl/           연합학습 서버·클라이언트, 집계
rag/          조항 단위 색인과 검색
evaluation/   공통 예측 스키마 · 단일 채점기 · 지표
tracking/     실험 추적, 체크포인트 규칙
docs/         설계 문서 · 개발 기록
```

## 데이터

원본 이미지·가중치·산출물은 저장소에 포함하지 않는다. 매니페스트와 스냅샷 해시만 추적한다.

규정 문서(IACS Rec.47, 한국선급 규정 등)는 **원문을 재배포하지 않는다.**
파싱 스크립트와 출처·판본·해시(`corpus/parse/sources.yaml`)만 두어, 원문을 직접 받으면
같은 결과를 재현할 수 있게 했다. 저장소에 두는 것은 조항 번호와 허용치 수치 같은 사실 정보다.
